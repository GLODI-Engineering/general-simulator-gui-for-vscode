# Handoff — waveform viewer, result format, and the mouse-driven test suite

State of branch `feat/ports-say-which-paradigm` as of 2026-11-08. Fifty-one
commits, none pushed. Written so another session can pick the work up without
re-deriving what was already settled.

## What is finished and measured

**The waveform viewer.** Plot theming, SI-prefixed axis ticks, per-trace display
gain, a measurements bar, a signal browser that adds any signal to any axes
(creating a new y-axis when the unit differs), past-run overlays with `[n]` age
labels, and export to PNG/SVG/CSV/JSON/`.gsim_sim_result`.

**The result format.** `.gsim_sim_result` is metadata (schema v2) that either
carries samples inline or points at an HDF5 file. Named for distance from
`.gsim_sym`, which the earlier `.gsim_sim` was too close to.

**Decimation.** Min/max envelope on a shared time grid, over the *visible
window* rather than the whole signal, all series reduced together so they stay
aligned. Implemented once in Rust (`crates/waveform-store`) and called from the
webview through WASM, so the browser and a future server run the same code.

Measured, not estimated:

| what | result |
| --- | --- |
| 25k x 11 signals, open | 220 ms |
| 2.75M points, open | 670 ms |
| full extent, points stroked | 2,728 (was 20,000) |
| zoomed to 0.76% of a run | 1,910 points, exact |
| Rust: 100M samples (763 MB) | 102 ms; 1% window 1.2 ms |
| `.wasm` size | 137 KB |

Decimation is linear from 1M to 100M samples.

**Property tests** (`crates/waveform-store/tests/properties.rs`, nine of them).
Max, min and peak-to-peak survive decimation **exactly** at every budget, and
every original sample is inside the drawn band. The mean holds to 0.03% while
buckets stay finer than the waveform's period and is structurally wrong once
they are coarser; RMS is biased high. My first claim that the mean was
structurally wrong at all budgets was falsified by the test and corrected.

**Storage.** gzip level 1 with the shuffle filter, chosen by measurement over
five candidates: 2.36 MB from 64 MB raw, 95 ms to write, 70 ms to read — smaller
*and* faster than the alternative it replaced.

**The test suite.** `tests/e2e/` drives the editor with real pointer travel,
drags and keystrokes. 492 catalog components insert and draw their ports; seven
same-domain connections and forty-two cross-domain refusals verified by actual
drag. The generic half is a separate repo, `gs-ui-probe`, linked in as
`"gs-ui-probe": "link:../gs-ui-probe"` — standard mouse and keyboard work with
nothing specific to this app in it. Per-experiment code lives in
`tests/e2e/scenarios/`.

## What is open

**A parameter write that silently does not apply.** In the signal-flow PLL drawn
by mouse, one of four `setParam(integrator, "den", "1, 0")` calls in
`tests/e2e/scenarios/sogi-pll.ts` does not reach the document:
`Transfer_function2` keeps the default `1/(s+1)` while the other three read
`1/s`. Likely the vector-parameter editor not committing, or a race between
committing one block and selecting the next. When fixed, assert in
`sogi-pll.spec.ts` that every integrator's `den` is `[1, 0]`, so it cannot
return quietly.

**A wire may name a port its block does not have.** The renderer does not refuse
it — it falls back to a position and draws the wire somewhere plausible. Whether
that leaves a diagonal, and so turns red, is luck. On the converter sheet this
hid twenty-seven bad endpoints and eighteen wires that were never drawn at all.
`scripts/check-wires.mjs` reports them, but it is a stopgap: the editor itself
should say so. Check against the ports a block *drew*, never the catalog —
`control.sum` and `extensibility.octfunc` generate ports from a parameter and
declare only the first, so a catalog check buries the real findings under false
ones.

**Live streaming never reaches the viewer.** The kernel sidecar accepts one
WebSocket connection ("Rejecting second WebSocket connection"), which the
schematic panel holds, so the waveform panel sees no chunks while a run is in
flight. The extension host has to broker them, the way it already brokers drags.

**The `/lod` endpoint** is built and tested but nothing calls it. No format
change is needed to wire it up.

**HDF5 reading in the Rust crate** is not written — native and a
WASM-compatible subset. gzip rather than the writer's previous filter makes this
straightforward.

**Catalog data**, found by the sweep, no fix attempted: 186 of 492 manifest
entries are exact duplicates, and `passive.switch.ideal` lists
`passive.switch.voltage` — another type's name — as an alias. Consecutive
toolbar inserts drop terminals on exactly the same point.

## Running things

```
pnpm -r test                                   # unit: 996 pass, 11 todo
pnpm --filter @gensim/frontend exec playwright test   # e2e; needs a browser
PLAYWRIGHT_BROWSER_CHANNEL=chrome pnpm ... # no bundled Chromium on Ubuntu 26.04
node scripts/check-wires.mjs --doc <sheet.gsim_sch>
node scripts/render-schematic.mjs --doc <sheet> --out render-out/x.png
node scripts/render-waveform.mjs --case buck|bode|dense|history|spike
node scripts/stress-waveform.mjs <file.gsim_sim_result>
cargo test --manifest-path crates/waveform-store/Cargo.toml
```

`render-out/` is gitignored on purpose: renders of non-public sheets go there
and must not be committed.

## Traps that cost time, so they are written down

- `uPlot.valToPos(v, scale, true)` returns *device* pixels from the chart
  corner; `false` returns CSS pixels from the *plot area* corner. A CSS overlay
  wants neither — use `overlayPx()`, which adds `u.over.offsetLeft/offsetTop`.
- Port hit areas are `<circle fill="none" stroke="none">`, which Playwright
  calls not visible. Measure them with `getBoundingClientRect` in the page.
- `import.meta.url` in a spec breaks: Playwright transpiles to CJS. Use
  `process.cwd()`.
- A bare `results/` line in `.gitignore` silently swallowed the whole result
  format implementation from `git add -A`. Negations added.
- Quick Insert is a double chord; one press opens the command palette.
- `pkill -f <pattern>` kills the issuing shell when the pattern appears in its
  own command line. Bracket a character: `gsim[-]profile`.
